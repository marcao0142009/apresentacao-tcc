SLIDE 07 • 1min15s

API e estrutura de dados

Para o funcionamento do nosso sistema, utilizamos uma API desenvolvida com Flask, responsável pela comunicação entre o frontend e o banco de dados.

Dentro dessa API, temos diferentes rotas, responsáveis pelo cadastro de usuários, login e gerenciamento dos dispositivos.

Utilizamos métodos HTTP, como GET para consultar informações, POST para cadastrar, PUT para atualizar e DELETE para excluir registros.

Quando uma requisição é realizada, o Flask recebe essas informações, valida os dados, identifica o usuário autenticado e executa a operação solicitada.

Já para o armazenamento, utilizamos o MySQL, que centraliza as informações dos usuários, dispositivos, análises técnicas, preços e feedbacks.

Dessa forma, conseguimos manter os dados organizados e realizar as operações de acordo com as permissões de cada usuário.

SLIDE 12 • 45s

Segurança e organização dos dados

Em relação à segurança do sistema, utilizamos o JWT, que é um token responsável por identificar o usuário autenticado e proteger as rotas da nossa API.

Também utilizamos recursos do Werkzeug para gerar o hash das senhas, evitando que elas sejam armazenadas em texto puro no banco de dados.

Além disso, implementamos um controle de acesso no backend, diferenciando as permissões dos clientes e dos administradores.

Todas essas informações são centralizadas no MySQL, e a autenticação é validada diretamente no servidor, não dependendo apenas da interface do sistema.

Memorize: JWT → Hash → Permissões → Segurança.
SLIDE 13 • 1min15s

Testes de software e validação

Para verificar o funcionamento do sistema, definimos testes funcionais e testes de acesso.

Nos testes funcionais, verificamos operações como cadastro, login, abertura e consulta de ordens de serviço, atualização de informações e envio e resposta de orçamentos.

Já nos testes de acesso, o objetivo é verificar a proteção das rotas pelo JWT e a separação das permissões entre clientes e administradores.

Por exemplo, um cliente deve conseguir consultar suas próprias solicitações, mas não deve ter acesso às funções administrativas.

Na validação prática, a proposta é utilizar duas contas, uma de cliente e outra de administrador, executando as tarefas de cada perfil e registrando possíveis erros, dificuldades e ajustes necessários.

O principal critério de validação é garantir que cada usuário consiga realizar suas tarefas sem acessar funcionalidades para as quais não possui autorização.

Memorize: Testes funcionais → Testes de acesso → Validação prática.

Atenção: não afirme que todos os testes passaram sem ter essa confirmação. O slide não apresenta os resultados.

Glossário técnico

API
Faz a comunicação entre as partes do sistema.
Flask
Framework Python utilizado no desenvolvimento do backend.
JWT
Token utilizado para identificar usuários autenticados.
Hash
Transformação da senha em um valor que não permite recuperar diretamente a senha original.
Werkzeug
Biblioteca Python utilizada, nesse projeto, para proteger as senhas com hash.
MySQL
Sistema de gerenciamento de banco de dados.
CRUD
Cadastro, consulta, atualização e exclusão de registros.
Backend
Parte do sistema responsável pelo processamento das informações e regras de negócio.
OS
Ordem de Serviço.
